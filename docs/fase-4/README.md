# Fase 4: documentación final del sistema

**Estado:** lista de control inicial. La documentación definitiva debe basarse en el código y el modelo de persistencia realmente entregados.

## Documentos a completar al finalizar la implementación

- [ ] Descripción final de la arquitectura y las responsabilidades de cada capa.
- [ ] Diagrama final de paquetes.
- [ ] Diagrama final de clases actualizado contra el código real.
- [ ] Tabla de clases con tipo, responsabilidad, atributos principales y métodos relevantes.
- [ ] Modelo entidad-relación definitivo de PostgreSQL.
- [ ] Diccionario de datos por tabla y columna.
- [ ] Tabla consolidada de GRASP, SOLID y Código Limpio con referencias concretas a clases y métodos.
- [ ] Resultados de pruebas funcionales y de integración.
- [ ] Manual técnico con configuración, instalación y ejecución.
- [ ] Manual de usuario con los flujos implementados.
- [ ] Reporte final del repositorio: commits por integrante, ramas creadas y fusionadas, y Pull Requests revisados.
- [ ] Bitácoras de uso de IA de los integrantes, completadas por cada persona.

## Reglas para evitar documentación ficticia

1. No presentar diagramas iniciales como diagramas finales sin revisarlos contra el código.
2. No completar modelo entidad-relación ni diccionario con tablas que todavía no se hayan diseñado e implementado.
3. No afirmar que una funcionalidad está terminada solo porque está descrita en los requerimientos.
4. Actualizar esta lista cuando haya evidencia real.
5. Mantener en español la documentación y los mensajes para el usuario, de acuerdo con la indicación del docente.
